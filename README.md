# Soit

把和 AI 的对话，变成可管理的探究。

Soit 是**本地 Agent Host**：你在卡片树里组织、恢复、分叉每一次对话探究，把沉淀下来的真知落到自己的 Obsidian 库里。数据全程在本地，模型自带 Key（BYOK），不需要云端账户。

---

## 产品特性

### 卡片即探究

每张卡片是一次**探究**，不只是聊天记录。它同时保存两样东西：

- **对话**：你与 AI 的完整交流
- **状态**：正在问什么、卡在哪、下一步做什么

一张卡片就是一条有来龙去脉的求知线索。

### 从对话长出卡片

- 回复里带下划线的文字（通常是概念）可以直接点开，先看**短解释**（不建卡）
- 想继续，就选一个方向：
  - **深挖**：垂直往下钻，继承父卡上下文
  - **发散**：平行展开一条新探究，留一条指向来源的边
- 换一种讲法用**重生**：仍在同一张卡内重来，不产生新卡

卡片树就是你的知识探索地图，正常学习 = 对话 → 点概念 → 选方向 → 进新卡继续。

### 两层记忆

| 层 | 是什么 |
|----|--------|
| **卡片** | 探究的工作区，活在 Soit 里 |
| **Obsidian** | 真实记忆：站得住的概念落到 `concepts/`，跨天还要用的残渣落到 `inquiry/` |

不把聊天记录一股脑镜像成笔记；你在 Obsidian 里改过的正文不会被覆盖。

### 文档陪读

对着库里的 Markdown / PDF 精读时，文档以**只读陪读面**与探究卡并排显示；划词仍走同一套「短解释 / 引用 / 深挖·发散」。编辑仍交给 Obsidian，Soit 只读不写回。

### 资料轨

把学习材料放进 `materials/`，点开即进入陪读，Obsidian 里同样可见。

### 自带模型（BYOK）

支持 OpenAI 兼容接口；对话与短解释可以分别指定不同的模型。

### 交给本机 Agent（可选）

把一张探究导出为任务单，交给本机 coding agent 执行，结果写回卡片。外部 agent 不拥有你的卡片树。

### 对外只读接口（MCP）

让你自己的 Coding Agent（Kimi Code / Claude Code / Cursor 等）**只读**读取 Soit 的卡片宇宙，把它当作理解你探究进展的语境入口。

### 视觉与表达

- 数学公式（KaTeX）与 Mermaid 图表（流程图、时序图等）自动渲染
- 卡片图谱视图，一眼看清探究之间的关系
- 多套主题配色，随喜好切换

## 如何使用

1. **安装**：下载 Windows 安装包运行（依赖 Microsoft Edge WebView2，Win10/11 通常已预装，缺失时会提示）。
2. **选库**：首次打开，选择一个 Obsidian vault。**一个 vault = 一个独立的卡片宇宙**，彼此的卡片互不相通。
3. **开始探究**：和 AI 对话。遇到不懂的概念，点下划线文字 → 看短解释 → 选「深挖」或「发散」，进入新卡片继续追问。
4. **沉淀**：稳定下来的概念，让 Agent 写进 Obsidian 的 `concepts/`；未决问题、下一步、卡住的地方写进 `inquiry/`。

你的探究数据跟着 vault 走——拷贝库，就等于拷走全部卡片宇宙。

## 系统架构

- **壳**：Tauri 2（Rust）+ React。本机独立进程，不是 Obsidian 插件，也不是云端产品。
- **数据**：一个 vault = 一个宇宙，数据存在库里的 `.soit/` 目录，跟着你的库走。
- **双轨 Agent**：
  - **主轨 · Inquiry Assistant**：卡内探究对话，一卡一上下文。
  - **副轨 · External Runtime**：可选的本机 coding agent，作执行后端，不拥有卡片树。
- **记忆**：卡片（探究工作区）+ Obsidian（真实内存）两层；Soit 只写概念页与残渣，不把聊天全文搬进库。
- **对外接口**：只读 MCP，供你自己的 Coding Agent 只读读取卡片宇宙。
