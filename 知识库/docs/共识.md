## 1. 身份

Soit 是本机 **Agent Host**。

第一性工作是 **会话操作系统**：让自我驱动的学习者能管理、整理、恢复、分叉会话。不是课程平台，不是测验机，不是目标锁。

用户对着内置 Agent 聊。卡片树是它的原生工作区（替代线性聊天栏和文件树）。Skills 跑在 Soit 里。支持 **BYOK**。
BYOK **目录**（供应商 + 模型）与 **用途槽** 分开：卡片对话走对话槽；点词/划词短解释走短解释槽。未指定短解释时跟随对话模型。

Obsidian 是官方记忆后端，不是第二个聊天框，也不是宿主。

## 2. 两层记忆

| 层 | 是什么 | 不是什么 |
|----|--------|----------|
| 卡片 | 虚拟文件。一次 **探究**（inquiry） | 不是概念闪卡，不是一篇笔记的镜像 |
| Obsidian | 真实内存。给人复访、检索、改写 | 不是会话存档，不是聊天导出目录 |

一张卡片同时有：

- **对话路径**：Agent 当前看见的工作记忆
- **探究状态**：在问什么、卡在哪、下一步、活/停

从对话里长出下一张卡片是主手势，不是附加功能。正常学习就是：和 AI 对话 → 某个概念不会 → 点下划线 → 短解释（可选）→ 选方向 → 进新卡片继续。新卡片仍是一张探究，不是一张词条。

### 2.1 文档陪读（只读对照，不是第三层记忆）

探究有时要对着 **材料**（vault 内 Markdown、PDF、纯文本等）读。Soit 提供 **只读陪读面**，与焦点探究卡并排，把「对话式探究」和「文档式精读」融在同一主循环里。

| 是 | 不是 |
|----|------|
| 当前探究的 **语境眼镜**（只读预览） | 第三种卡片节点 / 文件树产品 |
| 会话级对照（可记「这卡在看哪份路径」） | 第二套笔记编辑器 |
| 划词 → 同一套：短解释 / 引用进作曲 / 深挖·发散 | 文档批注线程、高亮同步工厂 |
| 打开单文件、限额读取 | 冷启动扫 vault、全文预览索引 |

规则：

- **卡始终是 C 位。** 文档默认分栏陪读，可短暂加宽或 peek，不可把产品做成「文档主 + AI 侧栏」。
- **编辑归 Obsidian。** Soit 内不写回 PDF/正文；不在 Soit 做完整 md 双向编辑。
- **AI 流式只进卡 turns**，不直接改打开的文件。
- **进地图模式时陪读面关闭或不可读**，禁止圆图 + 卡 + 文档三层叠罗汉。
- 文档 **不是** 卡 PiP：卡 PiP 仍是探究卡浮窗；陪读有独立会话状态（见 `doc-session-fsm.md`）。
- v1：**全局一次一个文档会话**；可选显示绑定的焦点卡。多文件 tab、批注落库后置。

### 2.2 资料目录与资料轨

用户上传/导入的学习材料，落在 **当前 vault 的 `materials/`**（Obsidian 同一文件夹可见），**不进** `.soit/`、不进 `universe.db` blob。

| 是 | 不是 |
|----|------|
| vault 内真文件 + 右侧 **资料轨** 浅列表 | 第二套云盘 / 文件树产品主 IA |
| 点文件 → 既有只读陪读（DocSession） | 第三种卡片节点 |
| 导入 = 复制进 `materials/` | 只记外部绝对路径当默认 |
| 与 Obsidian「同目录事实一致」 | 实时双向编辑同步 / 云同步 |

壳层：右上设置齿轮**下方**常驻「资料」按钮 → 展开/收起资料轨；状态机见 `materials-rail-fsm.md`。  
预览区与卡之间可 **拖分隔条** 调宽（比例本机记忆）。

## 3. 分叉

v1 只承认两种长卡方式：

| 方式 | 关系 | 上下文 |
|------|------|--------|
| **深挖** | 垂直。同一条探究往下 | 只带作用域：父卡状态 + 点中的原文 +「为什么跳下来」。需要时 Agent 再读父卡 |
| **发散** | 平行。同一层另一条 | 空白对话 + 一条指回源卡的边 |

规则：

- **重来不是新卡片。** 换一种讲法、再生成，都在同一张卡内部完成。旧回合可留在该卡历史里，树不为此分叉。
- **父卡不因发散而自动停住。** 两边都还活着。树是关系，不是一串强制暂停。
- **两边都能长卡**：用户和 Agent。
- **单击带下划线的文字（通常是概念）可先短解释（不建卡）；建卡前须先选深挖或发散，再进入新卡。** 不是静默深挖。

不在 v1 做：合并两条探究、把重来做成第三种卡片类型。

## 4. 写入 Obsidian

Agent 有写记忆的工具；用户也可以随时触发沉淀。

写出规则：

- 带指回源卡片的引用
- 不把整段 transcript 倒进库
- 用户在 Obsidian 里改过的正文，默认不覆盖

落库原子（不是一卡一笔记）：

| 原子 | 落点 | 何时 |
|------|------|------|
| 稳定下来的概念 | `concepts/` | 结论已经站得住 |
| 跨天还要用的残渣 | inquiry / log | 未决问题、下一步、卡住点、指回哪张卡 |

卡片本身只活在 Soit 宇宙里。

## 5. 宇宙与进程

- Soit 是 **本机独立进程**，不是 Obsidian 插件，不是云端产品，不挂在其他 Agent Host 上。
- **门厅选库、屋子探究：** 冷启动先停工作区门厅选本机 vault，点进入后再开宇宙；探究与三栏壳只在屋子内。
- 在 App 里选定一个 Obsidian vault。
- **一个 vault = 一个卡片宇宙**，彼此隔离。
- 宇宙物理位置：`vault/.soit/universe.db`。跟着 vault 走。拷贝 vault = 拷贝宇宙。
- `.soit/` 不是知识库。Wiki 仍是给人看的 Markdown。Obsidian 把 `.soit` 当普通应忽略目录。
- 壳：**Tauri + Web 前端**。界面按成品做。

## 6. 技能

v1 技能 = 可修改的 **SKILL.md**。

- 内置 **4 个对话方法技能**：苏格拉底式提问、费曼输出评价、类比引导、回想式提问
- 它们只作用于 **对话行为**（怎么问、怎么评价、怎么讲），不提供卡片树写操作、不整理 Obsidian 笔记
- 主轨 Agent 的工作范围 = 项目对话；建卡 / 删卡 / 沉淀走产品 UI（或未来正式工具 API）
- Agent 能启用 / 停用 / 改写
- 人也可以改文件，改完即生效
- v1 无代码插件、无插件市场
- 目录结构预留以后接代码插件的门，v1 不实现
- 旧版 organize-cards / organize-obsidian 技能已废弃，可手动删除

## 6.1 Agent 双轨

Soit 是 **会话 Host**：卡片宇宙与探究语法的权威在 Soit，不在外部 agent session。

| 轨 | 角色 | 说明 |
|----|------|------|
| **主轨 Inquiry Assistant** | 卡内探究对话 | 一卡一上下文；BYOK 或 Mock；深挖 / 发散 / 重生规则不变；可走 **有限 Host 工具**（库内检索 / 读 URL / 可选网页搜索，步数有上限） |
| **副轨 External Runtime** | 可选执行后端 | 本机 coding agent（CLI/ACP 等）作 **工具级 handoff**；导出 brief → 运行 → 结果写回 turn/残渣；**不拥有**卡片树 |

主轨工具：

- 固定工具目录 + 轮次上限；结果进回合 **过程区**（与思考同一折叠入口）；正式回答只在 turns 正文。
- **不是** 完整 Agent Core、无界 ReAct、shell/写树舰队。

禁止：

- 把外部 session 目录当作卡片源或宇宙权威
- 以「Soit 作为其他 Host 的插件」为默认路径
- v1 子 Agent 舰队 UI

实现细节见 `docs/superpowers/specs/2026-08-20-agent-dual-track-spec.md`（v1.2）与 `docs/superpowers/specs/2026-08-21-inquiry-tools-search-spec.md`。

### 6.2 反向只读 MCP 接口（让外部 agent 只读读取）

Soit 提供**反向只读 MCP 接口**，让用户自己的 Coding Agent（Kimi Code / Claude Code / Cursor 等）只读读取卡片宇宙（探究状态 + 对话）。方向与 §6.1 副轨 handoff 相反，互不冲突。

| 是 | 不是 |
|----|------|
| 只读读取快照（cards / turns / edges） | 写库、造卡、改 Obsidian 的出口 |
| 用户 agent 的**语境入口** | 卡片权威的替代（权威仍在 `universe.db`） |
| stdio 子命令（继承用户身份） | 默认对网络开放的常驻服务 |

规则：

- **只读**：工具白名单，无写工具、无裸 SQL。
- **形态 v1**：`soit mcp serve` stdio 子命令，直接以只读连接打开 `vault/.soit/universe.db`；不随 App 冷启动、不常驻。
- **App 内嵌 loopback HTTP（随机 token）为 P1 后置**；不阻塞 P0。
- 默认关闭；用户显式配置客户端（`mcp.json`）才生效。

## 7. v1 闭环（成品，不是原型）

必须同时成立：

- 卡片功能完整（树 / 堆叠导航算主循环，要做好）
- 对话功能完整
- Obsidian 整理体系能用、能成熟运转
- BYOK
- 前端观感按可天天用的产品做，对标 Explore、DSH 的完成度

明确后置：

- 技能编辑 GUI / 市场
- MindScape 级「思维宇宙」
- 第二套笔记编辑器
- 子 Agent 舰队
- 文档批注线程 / 高亮写回 Obsidian / NotebookLM 式多源工作室
- 多文档 IDE、vault 全文预览索引、Soit 内 live 编辑 md

## 8. 默认（未单独拍板，按此做；要否现在改）

- v1 **单探究助手 + 可选外部 Runtime**（工具级 handoff，非多 Agent 舰队）
- 前端 **React**
- 回复里由 Agent 标出可点概念；用户也可以选中任意文本再分叉
