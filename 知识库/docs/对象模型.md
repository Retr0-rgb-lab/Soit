# 对象模型

与 [共识.md](./共识.md) 一致。这里只写实体、关系和不可变规则。

## 进程与仓库

```
Soit App (Tauri + Web)
  └── 打开一个 vault 路径
        ├── .soit/universe.db     # 卡片宇宙（Soit 源）
        ├── .soit/skills/         # 本宇宙可改写的 SKILL.md（可后补）
        ├── .soit/runs/           # External Runtime handoff 沙箱（日志/staged brief；非宇宙源）
        ├── concepts/             # 真实内存：概念页
        └── （inquiry / log）     # 真实内存：残渣。具体目录名实现时再定
```

不变量：

1. 同时只操作一个 vault，即一个宇宙。
2. 换 vault = 换宇宙。卡片、边、未写出的会话状态不串库。
3. `universe.db` 跟着 vault 走，不跟着 App 安装目录走。
4. Obsidian 只是该目录的阅读器 / 第二编辑器。Soit 不嵌入 Obsidian 进程。

## 卡片（探究）

一张卡是一次 inquiry，不是一篇笔记，不是一个概念词条。

最低字段（逻辑，不是表结构定稿）：

| 字段 | 含义 |
|------|------|
| id | 稳定主键 |
| title | 这张探究叫什么 |
| status | 至少：活 / 停 / 完成 |
| parent 边 | 见下 |
| messages | 该卡的对话路径 |
| question | 正在问什么 |
| stuck | 卡在哪（可空） |
| next | 下一步（可空） |
| created_at / updated_at | 时间 |

对话路径是 Agent 在这张卡里实际看见的工作记忆。  
状态字段才是「虚拟文件」里跨天要保住的东西。

## 边

只有两种用户可见的长卡边：

| 边 | 从 | 到 | 附带 |
|----|----|----|------|
| 深挖 | 源卡 + 源跨度（下划线/选区） | 子探究 | 作用域上下文：父状态 + 原文 + 为何跳下 |
| 发散 | 源卡 + 源跨度 | 平行探究 | 不带对话；只留回边 |

补充规则：

- 重来、再生成、换讲法：**不建边**，只在源卡的 messages 里追加或分叉回合。
- 删除规则以后再定；不得在未定义时级联毁掉用户的 Obsidian 正文。
- 回边是一等公民：从子卡能回到源跨度，从源跨度能找到已长出的卡。

## 上下文继承

发送到模型的上下文必须可解释，且按边类型固定：

**深挖**

- 本卡已有 messages
- 父卡 inquiry 状态（question / stuck / next / title）
- 源跨度原文
- 一句「为什么从这里跳下来」
- **不**自动附带父卡全文 transcript

需要更多父卡内容时：Agent 用工具去读，而不是预灌进 prompt。

**发散**

- 本卡 messages（新卡为空）
- 一条指向源卡/源跨度的引用，供人导航，不默认进 prompt 全文
- 父卡保持活

## 消息

消息属于卡片，不属于宇宙根。

角色至少：`user` | `assistant`（实现时可加 `system` / `tool`）。

卡片内的「重来」是卡内操作：保留旧回合，另开一条同卡内的尝试。这不是树上的第三种节点。

## 下划线手势

1. Agent 在回复里标出可点概念（默认）。
2. 用户也可选中任意文本（**卡内 turns 或陪读文档**）。
3. 点击标记或划词可先短解释（不建卡、不落库）；建卡仍须显式选深挖或发散。
4. Agent 也可以建卡，遵守同一套边与继承规则。

## 文档引用（陪读，非卡片）

文档不是树上的节点。逻辑实体：

### DocRef（稳定引用）

| 字段 | 含义 |
|------|------|
| path | vault 内相对路径（权威）；打开时 Host canonicalize 且必须落在当前 vault 根下 |
| kind | `md` \| `text` \| `pdf` \| …（探测结果） |
| displayName | 展示用文件名 |

v1 **不**把二进制 blob 写入 `universe.db`；不镜像整文件进卡片。

### DocSession（运行时会话）

| 字段 | 含义 |
|------|------|
| status | closed / loading / ready / error / closing |
| ref | 当前 DocRef |
| layout | split / doc-wide / peek |
| boundCardId | 可选，服务哪张探究 |
| cursor | 页码 / 滚动 / 选区 |

- 同时最多 **一个** 活跃 DocSession（v1）。
- 换 vault / 解绑 → 会话必须关闭。
- 进 map → 会话关闭（或等价不可读；实现选关闭）。

### DocAnchor（选区锚点）

从文档划词产生，可进入：

- Composer 引用（本轮 user 文本）
- 深挖 / 发散的 `SourceSpan` 扩展字段（可选）

| 字段 | 含义 |
|------|------|
| path | 同 DocRef.path |
| text | 选中原文 |
| page | PDF 页码（可选） |
| offset / end | 文本偏移（可选） |

### SourceSpan 扩展（可选字段）

既有：`turnId`、`text`、`markId`、`start`、`end`。

文档起源时 **额外可选**：

| 字段 | 含义 |
|------|------|
| docPath | vault 相对路径 |
| docPage | PDF 页 |
| docKind | 类型提示 |

规则：

- 仅卡内起源时不必填 doc* 字段（向后兼容）。
- 深挖上下文仍只带 **作用域摘录**（锚点 text + 页码线索），**不**整份 PDF/md 预灌 prompt。
- 需要更多材料时：后置「Agent 读文件工具」；v1 以人眼陪读 + 摘录引用为主。

### 与 Composer 附件

| | Composer 附件 | DocRef / DocSession |
|--|---------------|----------------------|
| 生命周期 | 发送前本地 chip | 陪读会话；可记 boundCardId+path |
| 二进制 | 仅文件名进 user 文本 | PDF 只读渲染，不进 prompt 全文 |
| 文本 | 可 inline 截断进 user | md/text 预览；引用走 DocAnchor |

## Obsidian 投影

Soit → vault 的写出是单向工具调用，加上用户手动沉淀。

| 写出物 | 内容 | 约束 |
|--------|------|------|
| 概念页 | 一个站得住的概念 | 一概念一页；已有且被用户改过则不覆盖全文 |
| 残渣 | 未决问题、下一步、卡住点、卡片 id | 可追加；必须能指回卡片 |

禁止：

- 把整张卡镜像成一篇 `.md`
- 把 `universe.db` 的内部结构展开成人应维护的笔记树

## 技能

技能是文本，不是代码。

- 内置：整理卡片、整理 Obsidian
- 可被 Agent 启用 / 停用 / 改写
- 人改文件即生效
- v1 不加载任意可执行插件
